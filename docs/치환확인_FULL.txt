프로젝트 명

**PitchLens(피치렌즈)** — AI 기반 발표 피드백·코칭 플랫폼

프로젝트 개요

가. 개요

대학 강의, 캡스톤 발표, 취업·창업 피칭 등에서 **발표 역량**은 학습 성과와 직결되는 핵심 역량이다. 그러나 교실 환경에서는 강사·동료가 모든 학습자의 발표를 반복 청취하고, 슬라이드 내용 대비 실제 발화의 일치 여부, 말의 속도, 불필요한 추임새(필러), 논리 전개 등을 **슬라이드 단위**로 정밀하게 피드백하기 어렵다.

**PitchLens**는 이러한 문제를 해결하기 위해, 사용자가 **PPT·PDF 발표 자료**를 업로드하고 **슬라이드별로 웹에서 녹음**한 뒤, 서버가 자동으로 **음성 전사(STT)**, **말하기 속도·필러 분석(지도학습)**, **슬라이드·발화 일치도 및 개선안 생성(LLM)** 을 수행하는 통합 플랫폼이다.

첫째, OpenAI **Whisper**로 슬라이드별 발화를 텍스트로 변환한다. 둘째, 팀이 수집·라벨링한 음성 데이터로 학습한 **로지스틱 회귀 모델**이 발화 속도(느림/보통/빠름)와 필러(보통/많음)를 판별한다. 셋째, **GPT-4o**가 슬라이드 텍스트·전사문·음성 지표·(선택)슬라이드 이미지를 바탕으로 **슬라이드별·종합 피드백**을 생성한다. 넷째, **관리자 콘솔**을 통해 사용자·발표 세션을 운영·모니터링할 수 있다.

이를 통해 학습자는 객관적 지표와 구체적 개선안을 바탕으로 **자기주도적 발표 연습**이 가능해진다.

나. 설계의 주안점

- **슬라이드 단위 동기화**: 발표 자료와 녹음을 한 화면에서 슬라이드별로 연결하여, 슬라이드마다 독립적인 분석·피드백 제공  
- **역할 분리**: 속도·필러는 **학습된 ML 모델**이 계산하고, 내용·구성·유사도는 **LLM**이 담당하여 “AI 학습 + 생성형 AI” 요구를 동시에 충족  
- **마이크로서비스**: 인증·발표 관리(Spring Boot), 음성 분석(FastAPI), 피드백 생성(FastAPI)을 분리하여 확장·유지보수 용이  
- **클라우드 직접 업로드**: AWS S3 **Presigned URL**로 대용량 PPT·오디오를 클라이언트에서 직접 업로드하여 서버 부하 감소  
- **보안**: JWT 인증, USER/ADMIN 역할 분리, 서비스 간 내부 API 시크릿  
- **사용자·관리자 앱 분리**: 일반 사용자(`pitchlens-frontend`)와 관리자(`pitchlens-admin`)를 별도 앱으로 구성, Capacitor로 모바일 패키징 지원  

다. 기대 효과

- 슬라이드별 **유사도 점수·시각·내용 피드백**으로 발표 준비 시간 단축  
- WPM·필러 비율 등 **정량 지표**로 반복 연습 시 개선 여부 확인  
- 교육자·운영자의 **보조 평가·데이터 관리** 도구 제공  
- STT·ML·LLM·클라우드·웹 보안을 통합한 **IT융합 실습** 사례 확보

Ⅱ. 본    론

1. 배경 지식

가. LLM(대규모 언어 모델)

1) LLM이란?

대형 언어 모델(LLM, Large Language Model)은 인간의 자연어를 이해하고 생성할 수 있는 인공지능 모델로, 자연어 처리(NLP) 분야의 핵심 기술이다. 수십억~수천억 개의 파라미터를 갖는 신경망이 대량의 텍스트로 **사전 학습(Pre-training)** 된 뒤, 특정 작업에 맞게 **미세 조정(Fine-tuning)** 또는 **프롬프트**만으로 다양한 과제(요약, 질의응답, 생성 등)를 수행할 수 있다.

2) LLM의 주요 특징

- **대규모 데이터 학습**: 뉴스, 도서, 웹 등 방대한 말뭉치로 언어 패턴·문맥 학습  
- **Transformer 아키텍처**: Self-Attention으로 단어 간 관계를 병렬적으로 모델링  
- **문맥 기반 생성**: 이전 대화·입력 문맥을 반영한 자연스러운 출력  
- **다작업 처리**: 하나의 모델로 평가·생성·번역 등 복수 NLP 작업 가능  

3) 본 프로젝트에서의 LLM 활용

PitchLens는 **GPT-4o**를 발표 **내용·구성·슬라이드-발화 일치도** 평가에 사용한다. 입력으로 슬라이드별 추출 텍스트, Whisper 전사문, `Audio_analysis`의 WPM·속도·필러 라벨, (선택)슬라이드 이미지를 제공한다. LLM은 속도·필러 수치를 **직접 추정하지 않고**, ML이 계산한 지표를 **근거**로 피드백 문장·개선안·유사도 점수를 생성한다. 이는 교수님의 “학습 기반 속도·필러 판단 + AI 피드백” 지도 방향과 일치한다.



나. STT(음성 인식)

1) STT의 개념

Speech-to-Text(STT)는 사용자의 음성을 텍스트로 변환하는 기술이다. 발표 녹음을 전사해야 슬라이드 텍스트와 비교·WPM·필러 분석이 가능하므로, PitchLens 파이프라인의 **필수 전처리** 단계이다.

2) OpenAI Whisper

본 프로젝트는 **OpenAI Whisper**를 DeliveryLearning 서버에서 사용한다. 다국어·잡음 환경에서 실용적 인식률을 제공하며, `verbose_json` 응답으로 **세그먼트·재생 시간**을 확보하여 WPM 계산에 활용한다. 환경 변수에 따라 **Whisper API(`whisper-1`)** 또는 **로컬 openai-whisper** 모델을 선택할 수 있다.

한국어 전사 시 띄어쓰기가 불완전한 경우를 대비해, `features.py`에서 연속 한글·영숫자 덩어리를 토큰으로 분리하여 단어 수·필러 매칭 정확도를 높였다.



다. 지도학습 기반 발화 분석

1) 발화 속도(WPM)

WPM(Words Per Minute)은 분당 단어(또는 어절) 수로, 발표 전달력의 대표 지표이다. 본 시스템은 전사 텍스트의 토큰 수와 `duration_sec`로 WPM을 산출한다.

2) 필러(추임새) 분석

필러는 “음, 어, 그러니까, 근데” 등 발화 흐름을 끊는 표현이다. `consts.py`의 **FILLER_WORDS** 사전과 경계 규칙 기반 매칭으로 `filler_count`, `filler_ratio`를 계산한다. 2글자 이상 필러를 우선 매칭해 「근데」 안의 「근」 등 **오탐**을 줄인다.

3) 로지스틱 회귀 분류

팀이 `voice/` 폴더에 수집한 녹음과 **speed_label**(느림/보통/빠름), **filler_label**(보통/많음)로 **지도학습**을 수행한다. `build_feature_vector`로 WPM·필러 비율·단어별 카운트 등 특징 벡터를 만들고, **StandardScaler + LogisticRegression** 파이프라인 2개(`speed_model`, `filler_model`)를 `joblib`으로 저장한다. 추론 결과는 `Audio_analysis` 테이블에 기록되어 GPT 프롬프트에 전달된다.



라. AWS 및 클라우드 스토리지

1) Amazon S3

발표 PPT·슬라이드별 오디오는 용량이 크므로 **AWS S3**에 저장한다. 리전은 `ap-northeast-2`(서울)를 사용한다.

2) Presigned URL

Spring Auth 서버가 **Presigned URL**을 발급하면, 클라이언트가 애플리케이션 서버를 거치지 않고 S3에 **직접 PUT**한다. 이는 대용량 업로드 시 메모리·대역폭 부담을 줄이고, 보안 전공 관점에서 **최소 권한·시간 제한 URL** 패턴을 실습한다.

가. 시스템 전체 구성도

**분석 흐름 요약**

1. 발표 세션 생성 → PPT·오디오 S3 업로드  
2. DeliveryLearning: 전사 + 속도·필러 ML → DB 갱신  
3. Feedback API: 슬라이드 추출 + GPT 피드백 → DB 저장 → 클라이언트 표시  



나. 클라이언트 구조

1) 로그인 / 회원가입

`[그림 — 로그인·회원가입 화면 캡처]`

앱 실행 시 로그인 화면이 표시된다. 이메일·비밀번호로 로그인하며, 회원가입 화면에서 계정을 생성한다. Auth Server는 BCrypt로 비밀번호를 해싱하고 **JWT**를 발급한다. 토큰은 `localStorage`에 저장되며, 이후 API 요청 시 `Authorization: Bearer` 헤더로 전송한다. 로그아웃 시 **토큰 블랙리스트**에 등록하여 재사용을 방지한다.

2) 발표 자료 업로드

`[그림 — 업로드 화면]`

사용자는 **PDF, PPTX, PPT**를 업로드한다. PDF는 **pdfjs-dist**로 브라우저에서 슬라이드를 렌더링한다. PPT/PPTX는 Feedback API의 `POST /api/v1/slides/preview`로 미리보기 이미지·텍스트를 받거나, 변환 실패 시 플레이스홀더로 폴백한다. 업로드 완료 후 **녹음 단계**로 전환된다.

3) 슬라이드별 녹음

`[그림 — PresentationRecorder 전체화면]`

`PresentationRecorder`와 `useSlideRecorder`가 슬라이드별 녹음을 담당한다. **MediaRecorder API**로 webm/ogg 형식 녹음을 수행한다. **이전 슬라이드로 이동 시** 현재·이전 슬라이드 녹음을 삭제하고 재녹음하도록 하여, 슬라이드 인덱스와 오디오의 **일대일 대응**을 유지한다. 녹음 완료 후 `runAnalysis`가 분석 파이프라인을 시작한다.

4) AI 피드백 결과

`[그림 — FeedbackReviewer 결과 화면]`

`useAnalysis`는 `UPLOADING → TRANSCRIBING → GENERATING → DONE` 상태를 `ProgressOverlay`에 표시한다. 완료 후 `FeedbackReviewer`에서 **종합 점수·슬라이드별 유사도·시각 피드백·음성 요약(WPM, 속도·필러 라벨)** 을 확인한다.

5) 마이페이지

`[그림 — MyPage 목록·상세]`

과거 발표 목록·상세(전사·오디오 URL·피드백)·삭제·**PDF보내기**(`feedbackPdfExport`) 기능을 제공한다.

6) 관리자 콘솔

`[그림 — Dashboard, Users, Presentations]`

`pitchlens-admin`(포트 3001)은 **ADMIN** 역할 JWT로 `/api/v1/admin/**`에 접근한다. 대시보드 통계, 회원 목록·역할 변경, 전체 발표·상세 조회·강제 삭제를 수행한다. 768px 이하에서는 하단 탭·카드 UI가 적용된다.

패키지: `com.capstone.auth_server` · 포트 **8080**

라. AI 서버 구조

1) 음성 분석 서버(DeliveryLearning)

| 항목 | 내용 |
| 프레임워크 | FastAPI, Uvicorn |
| 포트 | 8765 |
| 엔드포인트 | `POST /api/v1/voice/analyze`, `POST /api/v1/voice/analyze-by-feedback` |

**처리 흐름 (`voice_job.run_feedback_voice_analysis`)**

1. DB에서 `feedback_id`에 연결된 S3 오디오 키 조회  
2. S3 다운로드 → 임시 파일 저장  
3. `transcribe_then_label_with_bundle`: Whisper 전사  
4. `build_feature_vector` → `speed_model`, `filler_model` 예측  
5. `Audio_analysis` UPDATE (transcript_text, wpm, filler_count, speed_label, filler_label 등)  

내부 호출 시 `X-Delivery-Learning-Secret` 헤더로 무단 접근을 제한할 수 있다.

`[표 — API 요청/응답 예시]`

2) 피드백 생성 서버(Presentation Feedback API)

| 항목 | 내용 |
| 프레임워크 | FastAPI |
| 포트 | 8001 |
| 엔드포인트 | `POST /api/v1/feedback`, `POST /api/v1/slides/preview` |

**`POST /api/v1/feedback` 흐름**

1. DB·S3에서 발표·`Audio_analysis` 로드  
2. 전사 누락 시 DeliveryLearning `analyze-by-feedback` 호출  
3. S3에서 PPT 다운로드 → LibreOffice(`soffice`)·PyMuPDF·python-pptx로 슬라이드 텍스트·이미지 추출  
4. `GPTService.generate_feedback` (GPT-4o, `use_vision` 옵션)  
5. `feedback_result`, `feedback_slide_result` 저장 후 JSON 반환  

**GPT 입력**: 슬라이드 텍스트, 전사문, WPM·필러 라벨, (선택)슬라이드 이미지 base64  
**GPT 출력**: `overall_similarity_score`, 슬라이드별 `similarity_score`, `visual_feedback`, `improvement_suggestions` 등

Ⅲ. 결    론

1. 결론

가. 발표 자료 업로드·슬라이드별 녹음

PitchLens는 PDF·PPTX·PPT 업로드 후 브라우저에서 **슬라이드별 녹음**을 수행한다. PDF는 클라이언트 렌더링, PPT는 서버 미리보기 API를 활용한다. 이전 슬라이드 이동 시 녹음을 초기화하는 규칙으로 **슬라이드-오디오 정합성**을 유지한다.

나. 음성 분석(전사·속도·필러)

Whisper로 슬라이드별 전사를 수행하고, 팀 학습 데이터 기반 **로지스틱 회귀**로 말하기 속도·필러를 라벨링한다. 결과는 DB에 저장되어 이후 GPT 피드백의 **객관적 근거**가 된다.

다. AI 피드백

GPT-4o가 슬라이드·전사·음성 지표를 종합하여 **슬라이드별 유사도·시각 피드백·종합 개선안**을 생성한다. 사용자는 점수와 문장형 코칭을 동시에 확인할 수 있다.

라. 마이페이지·관리자 기능

마이페이지에서 발표 이력·상세·PDF보내기가 가능하다. 관리자는 별도 앱으로 회원·발표를 모니터링·관리할 수 있어 **서비스 운영** 가능성을 검증하였다.

2. 기대 효과

**가. 발표 연습**

1) 슬라이드 단위 피드백으로 **어떤 장면을 고칠지** 명확해진다.  
2) 반복 연습 시 WPM·필러·유사도 추이로 **개선 여부**를 확인할 수 있다.

**나. 교육·캡스톤**

1) 강사·동료 청취 없이도 **1차 자동 피드백**이 가능하다.  
2) 발표 준비 시간을 단축하고, 객관 지표 기반 코칭이 가능하다.

**다. 기술·학과 연계**

1) JWT·S3·마이크로서비스·ML·LLM을 통합한 **융합 설계** 사례가 된다.  
2) 컴퓨터정보·보안전공의 웹 보안·클라우드 실습과 연계된다.

PitchLens는 발표 자료·슬라이드별 녹음·STT·지도학습·LLM을 하나의 플랫폼으로 통합하여, **자기주도적이고 데이터에 기반한 발표 연습 환경**을 제공한다.

3. 개선 방안

- **실시간 STT·라이브 코칭**으로 연습 중 즉시 피드백  
- ML 학습 데이터 확대 및 **딥러닝 모델** 검토  
- 슬라이드 병렬 전사·비동기 큐로 **분석 시간 단축**  
- 발표 **영상·자세** 비전 AI 연동  
- 녹음 데이터 **보존·삭제 정책** 및 OWASP 기준 보안 점검  
- LMS·과제 시스템 연동
